# Визуализатор зависимостей NuGet — вариант 5

Практическая работа № 2. Приложение анализирует зависимости пакетов NuGet
без использования пакетных менеджеров и сторонних библиотек для получения
зависимостей.

## Этап 1. Минимальный прототип с конфигурацией

Параметры читаются из CSV-файла с колонками `key,value`:

- `package_name` — имя анализируемого пакета;
- `repository` — URL репозитория или путь к тестовому файлу;
- `test_mode` — `true` для тестового репозитория или `false` для NuGet;
- `package_version` — версия начального пакета;
- `max_depth` — максимальная глубина анализа;
- `filter_substring` — подстрока для исключения пакетов.

Проверка ошибок конфигурации:

```bash
./scripts/run_invalid_config.sh
```

## Этап 2. Сбор данных

Для реального репозитория используется NuGet V3 Flat Container. Приложение
самостоятельно формирует URL файла `.nupkg`, скачивает его стандартным модулем
`urllib`, открывает как ZIP и извлекает зависимости из `.nuspec` через
`xml.etree.ElementTree`. Менеджеры пакетов и сторонние библиотеки не
используются.

## Этап 3. Основные операции

Полный граф строится алгоритмом BFS с очередью `deque`, без рекурсии.
Корневой пакет имеет глубину 0. Пакеты глубже `max_depth` не добавляются.
Пакет и его ветвь пропускаются, если имя содержит `filter_substring` без учёта
регистра. Множество уже обработанных вершин предотвращает бесконечный обход
циклических зависимостей.

Тестовый репозиторий — CSV-файл с колонками:

```text
package,version,dependency,dependency_version
```

Имена тестовых пакетов состоят только из заглавных латинских букв.

Готовые демонстрации:

```bash
./scripts/run_test_basic.sh
./scripts/run_test_depth.sh
./scripts/run_test_cycle.sh
./scripts/run_test_filter.sh
```

Запуск с реальным NuGet требует доступа к интернету:

```bash
./scripts/run_live_nuget.sh
```
